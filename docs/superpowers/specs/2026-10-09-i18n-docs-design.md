## 1. 목적

다른 나라 사람도 찾아 쓰게 한다. 화면과 CLI 문구의 기본 언어를 영어로 하고, 설정에서 한국어·일본어·중국어(간체)·독일어로 바꿀 수 있게 한다. README는 영어를 루트에 두고, 언어별 README를 `docs/`에 두어 서로 잇는다. README에는 실제 화면 스크린샷을 넣는다.

### 1.1 성공 기준

1. 설정이 없으면 화면·CLI·알림 문구가 영어다.
2. `config.toml`의 `language = "ko"`(또는 `ja`, `zh-CN`, `de`, `en`)로 언어를 바꾼다. 다음에 여는 팔레트·사이드 pane·CLI부터 그 언어다.
3. 사람이 읽는 문구는 모두 언어를 따른다: 화면, 하단 안내, 메뉴, 오류, CLI 출력, herdr 알림, 로그.
4. 언어마다 빠진 문구가 없다(컴파일러가 확인한다).
5. 루트 `README.md`는 영어이고 맨 위에 언어 링크가 있다. `docs/README.ko.md`·`README.ja.md`·`README.zh-CN.md`·`README.de.md`가 같은 내용을 그 언어로 담는다.
6. README마다 그 언어 화면의 스크린샷 세 장(팔레트, 사이드 pane, 상세)이 있다. 스크린샷은 가짜 데이터로 만들고, 다시 만들 수 있다(`cargo run --example screenshots`).
7. 기존 동작은 그대로다. 기존 테스트(한국어 문구를 확인한다)는 바뀌지 않고 통과한다.

### 1.2 범위 밖

- 시스템 로캘(`LANG`)로 언어 자동 고르기. 사용자가 기본은 영어라고 정했다.
- 실행 중에 언어 바꾸기(다음에 열 때 적용된다)
- Linear에서 온 글(상태 이름, 이슈 제목, 라벨)의 번역
- 검색어 문법 바꾸기. `s:진행`, `@나`, `p:긴급` 같은 한국어 별칭은 언어와 상관없이 계속 받는다.
- ROADMAP 언어별 분리(영어·한국어 그대로). 버전·ROADMAP 갱신은 릴리스 때 한다.
- 스페인어·프랑스어 등 다른 언어(나중에 같은 방식으로 더한다)

## 2. 언어와 설정

| 코드 | 언어 | 설정 값(대소문자 무시) |
|---|---|---|
| `en` | English (기본) | `en`, `english` |
| `ko` | 한국어 | `ko`, `kr`, `korean`, `한국어` |
| `ja` | 日本語 | `ja`, `jp`, `japanese`, `日本語` |
| `zh-CN` | 简体中文 | `zh`, `zh-cn`, `zh-hans`, `chinese`, `中文`, `简体中文` |
| `de` | Deutsch | `de`, `german`, `deutsch` |

- 설정: `config.toml` 맨 위 `language = "ko"`. 없으면 영어.
- 모르는 값이면 영어로 하고 설정 경고를 보인다(다른 설정 경고와 같은 방식).
- 적용: `cli::run`이 맨 처음 설정을 읽어 언어를 정한다. 그 뒤의 모든 출력(팔레트·사이드 pane·CLI·알림·로그)이 그 언어다.

## 3. 구조 (`src/i18n/`)

- `Lang` enum과 설정 값 해석, 지금 언어(`lang()`, `set_lang()`)
- `Texts` struct: 문구마다 필드 하나.
  - 고정 문구는 `&'static str`.
  - 값이 들어가는 문구는 `fn(…) -> String` 필드(값을 받지 않는 클로저를 쓴다).
- 언어마다 `static` 인스턴스 하나: `en.rs`, `ko.rs`, `ja.rs`, `zh_cn.rs`, `de.rs`. 필드를 하나라도 빠뜨리면 컴파일이 안 된다.
- 부르는 쪽: `t().tab_mine`, `(t().minutes_ago)(5)`.
- 지금 언어는 프로세스 전역 값(`AtomicU8`)이다. 네트워크 스레드에서 만든 문구도 같은 언어다.
- **테스트**
  - 단위 테스트(`cfg(test)`)에서 기본 언어는 한국어다. 그래서 한국어 문구를 확인하는 기존 테스트가 그대로 통과하고, 한국어 카탈로그가 지금 문구와 같다는 회귀 검사가 된다.
  - 다른 언어를 확인하는 테스트는 스레드별 덮어쓰기(`with_lang(Lang::En, || …)`)를 쓴다. 테스트는 저마다 스레드에서 돌아서 서로 섞이지 않는다.
  - 통합 테스트(`tests/`)와 실제 실행은 이 덮어쓰기가 없다.

## 4. 문구 옮기기 규칙

- 사람이 읽는 문자열은 모두 카탈로그로 옮긴다: 화면, 하단 안내, 메뉴, 상태, 오류(`ApiError`의 표시 문구 포함), CLI 출력, `anyhow` 오류 문구, herdr 알림, 설정 경고, 로그.
- **그대로 두는 것**
  - 검색어 별칭(`search::query`의 `"진행"` 등). 입력 어휘라서 언어와 상관없이 받는다.
  - 테스트 코드와 `test_support`
  - 설치 스크립트 출력(이미 영어)
- **한국어 카탈로그**는 지금 문자열을 한 글자도 바꾸지 않고 옮긴다. 기존 테스트가 이를 확인한다.
- **영어 문구 원칙**
  - 짧고 평이하게 쓴다. 문장은 sentence case로 쓰고, 짧은 이름표에는 마침표를 찍지 않는다.
  - 키 이름(`q`, `Esc`, `⏎`, `^K`)과 기호(`·`, `…`, `▶`)는 그대로 둔다.
- **폭에 기대는 곳**
  - 관계 칸 이름은 지금 8칸 고정이다. 이를 "그 언어 칸 이름 중 가장 넓은 것 + 2칸"으로 계산한다. 한국어는 지금과 같은 8칸이 되게 한다.
  - 다른 고정 폭(식별자 9칸, 우선순위 2칸)은 언어와 상관없다.
  - 하단 안내처럼 긴 줄은 화면 폭에서 잘린다(지금과 같다).
- **일본어·중국어·독일어**는 영어 문구를 그 언어로 자연스럽게 옮긴다. 화면 문구는 짧게 쓴다. 일본어는 です·ます체, 중국어는 간체, 독일어는 Sie 대신 간결한 명령형·명사형으로 쓴다(UI 관례).
- 옮기는 동안 일본어·중국어·독일어 카탈로그는 `..EN`(영어로 채우기)로 시작한다. 번역 단계에서 `..EN`을 없애 빠진 필드가 없게 한다.

## 5. 스크린샷 (`examples/screenshots.rs`)

- 가짜 데이터로 앱을 만들어 ratatui `TestBackend`로 그리고, 화면 버퍼를 SVG로 바꿔 `docs/images/<언어 코드>/`에 저장한다.
  - 파일: `palette.svg`(팝업 팔레트 120×30), `side.svg`(사이드 pane 64×30), `detail.svg`(상세 120×30)
  - 언어 코드: `en`, `ko`, `ja`, `zh-CN`, `de`
- **가짜 데이터**: 실제 Linear 데이터·사람 이름을 쓰지 않는다. 영어 이슈 제목, 흔한 라벨, 가상의 담당자 이름을 쓴다. 이슈 제목은 모든 언어에서 같다(이슈 제목은 사용자 데이터라서 번역 대상이 아니다).
- **SVG**
  - 셀마다 글자를 정확한 x 좌표에 놓아 글꼴 폭과 상관없이 칸이 맞게 한다.
  - 배경색이 있는 셀은 사각형으로 그린다.
  - 전경색·굵게를 반영한다.
  - 두 칸 글자(한글·한자·가나)는 두 칸을 차지한다.
  - 터미널 기본 배경은 어두운 색(`#1e1e2e`)이다.
- 다시 만들기: `cargo run --example screenshots`. 생성된 SVG는 저장소에 커밋한다. GitHub README에서 바로 보인다.

## 6. README

- 루트 `README.md`: 영어. 맨 위에 언어 링크 줄 `English · [한국어](docs/README.ko.md) · [日本語](docs/README.ja.md) · [简体中文](docs/README.zh-CN.md) · [Deutsch](docs/README.de.md)`. 지금의 한국어 절은 `docs/README.ko.md`로 옮긴다.
- 언어별 README는 같은 절 구성을 따른다.
  - 소개, 스크린샷, 기능, 필요한 것, 설치, API 키, 키, 검색어, 설정(`language` 포함), 파일, CLI, 문제 해결, 개발
- 이미지 경로는 각 파일 위치 기준이다. 루트는 `docs/images/en/…`, `docs/` 안은 `images/<언어>/…`.
- README 문구의 화면 문자열(메뉴 이름 등)은 그 언어 카탈로그와 같게 쓴다.
- 영어 README의 "The interface text is in Korean for now" 문장은 지운다.

## 7. 테스트

- `i18n`
  - 설정 값 해석(별칭, 대소문자, 모르는 값)
  - 기본 언어(단위 테스트에서는 한국어)
  - `with_lang` 덮어쓰기
  - 언어마다 대표 문구가 비어 있지 않고 서로 다른지
- `config`: `language` 읽기, 모르는 값이면 경고하고 영어로
- 옮긴 모듈마다 영어로 그린 결과를 확인하는 테스트 몇 개(화면 머리·하단 안내·관계 칸 폭·CLI 목록 안내·오류 문구)
- 관계 칸 폭: 한국어는 8칸, 영어는 가장 긴 칸 이름에 맞는다.
- 기존 테스트 341개(+1 무시)는 그대로 통과한다.
- 스크린샷 예제는 `cargo test`가 컴파일한다(`examples/`). 실행 결과(SVG)는 커밋해서 리뷰에서 본다.

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 옮기다 빠뜨린 한국어 문자열이 영어 화면에 남는다 | 옮긴 뒤 `src/`의 비테스트 코드에서 한글 문자열을 찾아, 검색어 별칭 말고는 없는지 확인한다(계획의 확인 단계) |
| 한국어 문구가 바뀌어 기존 동작이 달라진다 | 한국어 카탈로그는 지금 문자열을 그대로 쓰고, 기존 테스트가 한국어 기준으로 돈다 |
| 영어·독일어 문구가 길어 좁은 화면에서 잘린다 | 이미 폭에 맞춰 자르는 곳은 그대로 동작한다. 관계 칸 이름은 폭을 계산한다. 스크린샷으로 눈으로 확인한다 |
| 번역 품질 | 짧고 평이한 문구로 쓰고, 리뷰어가 언어마다 확인한다. 사용자가 나중에 고칠 수 있게 카탈로그가 한 파일씩이다 |
| 사용자 자신의 화면이 영어로 바뀐다 | 릴리스 노트·README에 `language = "ko"` 설정을 알린다. main 머지·릴리스는 사용자 확인 뒤에 한다 |
