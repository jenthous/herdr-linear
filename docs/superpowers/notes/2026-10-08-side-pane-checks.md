# 사이드 pane herdr 수동 확인 (v0.2.0)

- 날짜: 2026-10-08
- 환경: herdr 0.9.3, macOS. `scripts/deploy-local.sh`로 이 기기에 배포해서 확인했다.
- 이슈 제목·사람 이름·워크스페이스 이름은 적지 않는다.

## 확인한 것

| 확인 | 결과 |
|---|---|
| 새 매니페스트 | 배포만으로 `side` 액션이 보였다. herdr를 다시 켤 필요는 없었다 |
| 사이드 pane 열기 | 지금 pane 오른쪽에 열렸다. 시작 로그에 pane id와 워크스페이스 id가 남았다 |
| 기록 파일 | `side-panes.json`이 권한 0600으로 생기고 `{워크스페이스 id: pane id}`가 적혔다 |
| herdr로 pane 닫기 | 프로세스가 바로 끝나서 기록이 남았다. 설계대로다(스펙 7.3) |
| 기록이 남은 채로 키 누르기 | 기록의 pane이 없음을 확인해 기록을 지우고 새 pane을 열었다 |
| `q`로 닫기 | 사이드 프로세스가 자기 기록을 지웠다. herdr가 pane을 닫아서 빈 pane이 남지 않았다 |
| 목록 우선순위 | 좁은 사이드 pane에서 3칸 막대가 제목 자리를 많이 차지했다. 사용자 요청으로 1칸 막대와 회색 칸 게이지를 거쳐 P0~P3 색 라벨로 정했다(P0가 가장 급함, 스펙 4장) |

## 확인하지 못한 것

- 사이드 pane이 열려 있을 때 같은 키로 닫기.
  - `herdr pane process-info`의 실행 명령이 `…/herdr-linear ui --mode side`로 보이는지 실제 pane으로 보지 못했다.
  - 다르게 보이면 닫히지 않고 사이드 pane이 하나 더 열린다. 남의 pane은 닫지 않는다.
  - 배포 뒤 사용자가 확인한다.
- 사용자가 따로 결과를 알려 주지 않은 것
  - 가만히 둘 때 CPU
  - 1분 뒤 "방금 갱신"
  - hover 밝힘
  - pane 밖으로 마우스를 뺐을 때 남는 hover
  - 워크스페이스마다 하나인지
